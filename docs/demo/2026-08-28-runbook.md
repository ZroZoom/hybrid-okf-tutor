# Runbook demo — 28.08.2026

## Warunek rozpoczęcia

Przed uruchomieniem smoke testu osoba prowadząca potwierdza w [issue #3](https://github.com/ZroZoom/hybrid-okf-tutor/issues/3), że live endpoint OKF jest aktywny i dostępny dla aplikacji. Jest to warunek konieczny: bez live OKF nie ma dowodu, że fakt edukacyjny pochodzi z kontrolowanego źródła.

Nie wklejaj do czatu, dokumentacji, DevTools ani repozytorium wartości `OPENAI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` lub `OKF_EDGE_FUNCTION_URL`. W Vercel wartości te należą wyłącznie do środowiska serwerowego i żadna nie może mieć prefiksu `NEXT_PUBLIC_`.

## Scenariusz na 60 sekund

1. Otwórz wdrożony adres demo i kliknij **Rozpocznij demo**.
2. Gdy tutor zapyta o wzór, wpisz dokładnie `P=(a+b)*h/2` i wyślij odpowiedź.
3. Gdy tutor poprosi o podstawienie wartości, wpisz dokładnie `(6+10)*4/2` i wyślij odpowiedź.
4. W kroku obliczenia kliknij chip `___ cm²`. To jest wyłącznie pusty szablon, nie odpowiedź: edytuj jego treść w polu na `32 cm²`, a dopiero potem wyślij.
5. Potwierdź końcowy komunikat, że uczeń samodzielnie rozwiązał zadanie.
6. W panelu „Jak powstała pomoc” potwierdź widoczny ślad: `Luna`, `OKF` i `Reguła deterministyczna`; ślad OKF musi wskazywać atom `formula` dla trapezu.

Tutor nie może ujawnić wyniku liczbowego przed odpowiedzią ucznia w kroku obliczenia.

## Dwie próby negatywne

1. Uruchom demo ponownie i zamiast poprawnego wzoru wyślij błędny, np. `P=a*b`. Odpowiedź tutora ma wskazać etap do poprawy pytaniem pomocniczym; nie może zawierać `32` ani zdradzać wyniku jako pierwsza.
2. Uruchom fixture kryzysowy zgodnie z testem/środowiskiem smoke i wyślij komunikat klasyfikowany jako kryzys. Flow edukacyjny musi zostać zatrzymany, a odpowiedź musi zawierać `116 111` oraz `112`.

## Lokalna bramka przed PR

Uruchom w katalogu repozytorium:

```bash
pnpm test && pnpm lint && pnpm typecheck && pnpm build
git grep -nE 'sk-[A-Za-z0-9_-]{20,}|eyJ[A-Za-z0-9_-]{20,}\.' -- ':!pnpm-lock.yaml'
```

Warunek przejścia: wszystkie komendy jakości kończą się kodem `0`, a skan śledzonych plików nie wypisuje żadnej linii.

## Zewnętrzna bramka wydania — wykonuje controller po lokalnym przeglądzie

1. Wypchnij zatwierdzony branch i otwórz jeden PR do `main`.
2. Sprawdź, że job `Quality` jest zielony dla dokładnego SHA głowy PR — nie dla wcześniejszego commitu.
3. W projekcie Vercel `hybrid-okf-tutor` ustaw wyłącznie serwerowe: `OPENAI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` i `OKF_EDGE_FUNCTION_URL`; użyj integracji GitHub dla preview i production. Nie dodawaj repozytoryjnego sekretu z service-role.
4. Na gotowym wdrożeniu wykonaj pełny scenariusz i obie próby negatywne. W Network/DevTools potwierdź, że odpowiedzi i bundle JS nie zawierają API key ani service-role tokenu.
5. Po pierwszym zielonym workflow dodaj wymagany check `Quality` do istniejącego rulesetu `main`, zachowując PR-only, squash-only, resolved-thread, no-force-push i no-deletion.
6. Scal dopiero, gdy istnieją łącznie: zielony `Quality` na dokładnym SHA, gotowe wdrożenie Vercel, widoczny w śladzie live atom OKF `formula`, pełny scenariusz i negatywne próby zielone oraz pusty skan sekretów.
